## 0. Enmiendas bloqueantes al pseudocódigo de la spec de control

El pseudocódigo de `specs/v2.6_control_spec.md` §7 **no es implementable tal cual**: dos de sus cuatro ecuaciones
producen un producto que pasa AC4 y, sin embargo, no hace lo que dice hacer. Las dos enmiendas siguientes son
**obligatorias**; el resto del documento ya las incorpora. Medidas hechas con la cadena exacta de
`test/support/offline_chain.hpp` (biquads del SDK, `lr4 = 1`, `n = 1/4`, 1 kHz, pico 0,1 V, drive 11, `vol = 1`,
`mix = 1`).

### E1 — El coeficiente es de **paso**, no de polo (bloqueante)

| | Pseudocódigo §7 | Contrato v2.7 |
|---|---|---|
| Coeficiente | `coef = exp(-1/(fs*T))` | `coef = 1 - exp(-1/(fs*T))` |
| Uso | `env += coef * (x - env)` | `env += coef * (x - env)` |

Con `c = exp(-1/(fs·0.010)) = 0,99792` a 48 kHz, el polo del filtro es `1-c = 0,00208`, es decir
`τ = -1/(fs·ln(1-c)) = **3,4 µs** (0,16 muestras)`: el detector es **instantáneo**, no de 10 ms. El valor correcto
(`1-c = 0,00208…`) da `τ = 10 ms` exactos. La diferencia no es cosmética:

| Magnitud (TANH, drive 11, 1 kHz, n = 1) | Polo usado como paso | Paso correcto (`1-exp`) |
|---|---:|---:|
| `gainS` tras 1 actualización de un escalón unidad | 0,999999 | 0,00208 |
| `gainS` tras 5 actualizaciones | 0,999999 | 0,01039 |
| AC4: peor `\|dev\|` (9 curvas) | **0,018 dB** (pasa) | 0,815 dB (pasa) |
| AC4: `max\|out − in\|` con TANH drive 11 | **0,002092** | 0,62 (satura) |

**Consecuencia si se copia el pseudocódigo literal:** `gain` se recalcula muestra a muestra con los valores
instantáneos `|x|` y `|y|`, así que `out = y·(|x|/|y|) = x`: **la saturación desaparece** y el módulo se convierte en
un cable (error residual 0,0021 V, solo DC-blocker y cruce de bandas). El criterio AC4 **pasa igualmente** (de hecho
con más margen), por lo que el arnés no lo detecta: es un fallo de producto silencioso. De ahí que el contrato exija
el coeficiente de paso y que el listado de §1 se copie literal.

### E2 — `envOut` necesita attack/release, no solo release (bloqueante)

El pseudocódigo usa `coefRelease` para `envOut` siempre. Con una senoide estacionaria eso deja un rizado de
envolvente a 2 kHz de amplitud ~1 % que, tras el suavizado, se convierte en oscilación de nivel audible:

| Variante (9 curvas × n = 1/4, 18 puntos) | peor `\|dev\|` | peor p-p tras 200 ms | ¿AC4? |
|---|---:|---:|---|
| `envOut` solo release (§7 literal) | **3,010 dB** | **1,317 dB** | no (falla ambos) |
| `envOut` attack/release (§1) | 0,815 dB | 0,009 dB | sí |

La corrección es de una línea y no añade estado: `aO = (xo > envOut[b]) ? coefAttack : coefRelease`. El nombre
`coefAttack/coefRelease` del pseudocódigo ya implica este comportamiento; la rama que faltaba era un descuido, no una
decisión.

### E3 — La entrada del detector es la banda **pre-`curveDrive`** (aclaración obligatoria)

`dIn` se toma de la banda post-crossover **antes** de `curveDrive()`, no de `u`. Usar `u` multiplica la ganancia por
`drive`: con TANH, drive 11, la banda Mid pasaría de `gainS = 0,1199` (correcto) a `1,319` (**+20,8 dB**), y CLEAN
saturaría el clamp (`4,0` en vez de `3,5737`). No es una preferencia: es la diferencia entre calibrar y amplificar.

### E4 — Congelación en silencio (necesaria, no estaba)

`if (envIn[b] < AUTO_MAKEUP_GATE) continue;` con `AUTO_MAKEUP_GATE = 1e-3f` (−60 dBV). Sin ella, tras un silencio
`envIn` y `envOut` decaen a 0 y `g = 0/(0+1e-6) = 0`, con lo que `gainS → 0` y la primera señal tras el silencio
**sube desde cero** (swell audible de ~100 ms). Con la puerta, `gainS` conserva el último valor válido y la señal
entra al nivel correcto. Coste: una comparación por banda y muestra base.

## 1. `src/AutoMakeup.hpp` — fichero nuevo, header-only, sin Rack

### 1.1 Listado literal (copiar tal cual)

```cpp
#pragma once

#include <cmath>

namespace coaldynamics {

/** Umbral de "hay senal" del detector, en voltios (media |x| de banda).
    1e-3 V = -60 dBV. Por debajo el makeup es inaudible y gainS se congela. */
static const float AUTO_MAKEUP_GATE = 1e-3f;

/** Auto-makeup por banda (G2). Header-only, C++11, sin Rack, sin allocation,
    sin I/O: lo usan el modulo y el arnes offline. */
struct AutoMakeup {
  static const int BANDS = 3;

  float coefAttack;
  float coefRelease;
  float coefSmooth;
  float envIn[BANDS];
  float envOut[BANDS];
  float gainS[BANDS];

  AutoMakeup() {
    setSampleRate(48000.f);
    reset();
  }

  void setSampleRate(float sampleRate) {
    const float fs = (sampleRate > 0.f) ? sampleRate : 48000.f;
    coefAttack = 1.f - std::exp(-1.f / (fs * 0.010f));
    coefRelease = 1.f - std::exp(-1.f / (fs * 0.100f));
    coefSmooth = 1.f - std::exp(-1.f / (fs * 0.010f));
  }

  void reset() {
    for (int b = 0; b < BANDS; b++) {
      envIn[b] = 0.f;
      envOut[b] = 0.f;
      gainS[b] = 1.f;
    }
  }

  /** dIn/dOut: media de |senal| por banda, ya sin signo y >= 0. Se llama UNA
      vez por muestra base, nunca por submuestra de oversampling. */
  void update(const float dIn[BANDS], const float dOut[BANDS]) {
    for (int b = 0; b < BANDS; b++) {
      // Guarda de finitud: NaN o negativo -> 0. Es la identidad en el unico
      // dominio que produce el modulo (|L|,|R| >= 0 finitos) y evita que un
      // NaN de entrada envenene las envolventes para siempre.
      const float xi = (dIn[b] > 0.f) ? dIn[b] : 0.f;
      const float xo = (dOut[b] > 0.f) ? dOut[b] : 0.f;
      const float aI = (xi > envIn[b]) ? coefAttack : coefRelease;
      const float aO = (xo > envOut[b]) ? coefAttack : coefRelease;
      envIn[b] += aI * (xi - envIn[b]);
      envOut[b] += aO * (xo - envOut[b]);
      if (envIn[b] < AUTO_MAKEUP_GATE)
        continue;                       // silencio: gainS se congela
      const float g = envIn[b] / (envOut[b] + 1e-6f);
      if (!(g >= 0.f))
        continue;
      gainS[b] += coefSmooth * ((g > 4.f ? 4.f : g) - gainS[b]);
    }
  }

  /** Precondicion: 0 <= band < BANDS. Sin comprobacion en audio. */
  float gain(int band) const { return gainS[band]; }
};

} // namespace coaldynamics
```

### 1.2 Contrato de la API

| Símbolo | Semántica | Dominio | Coste |
|---|---|---|---|
| `AUTO_MAKEUP_GATE` | umbral de silencio del detector | constante, no configurable | 0 |
| `BANDS` | 3 (Low/Mid/High), inmutable | `static const int` | 0 |
| `coefAttack/coefRelease/coefSmooth` | coeficientes **de paso** a `fs` base | `(0,1)`; `fs > 0` | 3 `exp` por cambio de SR |
| `envIn[b]` | media recursiva de `\|banda\|` **pre-curva** | ≥ 0 | 2 flops/muestra base |
| `envOut[b]` | media recursiva de `\|curva·TRIM\|` **pre-makeup** | ≥ 0 | 2 flops/muestra base |
| `gainS[b]` | makeup suavizado, arranca en **1,0** | `[0,4]` | 2 flops/muestra base |
| `setSampleRate(fs)` | recalcula los 3 coeficientes; **no** toca el estado | `fs` base, nunca `fs·N` | 3 `exp` |
| `reset()` | `envIn = envOut = 0`, `gainS = 1` | — | 9 stores |
| `update(dIn, dOut)` | una iteración de los 3 detectores | arrays de 3, valores ≥ 0 | ~30 flops |
| `gain(b)` | lectura del makeup auto | `0 ≤ b < 3` | 1 load |

`update()` **no** devuelve nada y **no** puede fallar: no hay `throw`, ni `new`, ni `std::`, ni acceso a Rack.
`setSampleRate()` no llama a `reset()`: cambiar de SR no debe reiniciar la calibración (los detectores miden
amplitud, magnitud independiente de `fs`).

      satMidMeter = std::min(std::abs(wet[1][0] - u[1][0]), 1.f);
      satHighMeter = std::min(std::abs(wet[2][0] - u[2][0]), 1.f);

      // Auto-makeup (G2): UN detector por banda y muestra base. dIn = banda
      // post-crossover PRE-curveDrive (lowL/midL/upperL, no u); dOut =
      // post-curva post-TRIM (wet, antes de vol/pan/solo). Corre siempre,
      // este el modo activado o no.
      float dIn[3];
      float dOut[3];
      dIn[0] = 0.5f * (std::abs(lowL) + std::abs(lowR));
      dIn[1] = 0.5f * (std::abs(midL) + std::abs(midR));
      dIn[2] = 0.5f * (std::abs(upperL) + std::abs(upperR));
      for (int b = 0; b < 3; b++)
        dOut[b] = 0.5f * (std::abs(wet[b][0]) + std::abs(wet[b][1]));
      autoMakeupDsp.update(dIn, dOut);
    }
```

### 3.12 Flujo de audio con los dos puntos de inserción

```
IN_L ─┬─ DRY: delay(OS_LATENCY) → (1-mix)·dryGain ─────────────────────────────┐
      │                                                                       │
      └─ WET: up×N → LP/BP/HP ─┬─ dIn[b] = 0.5(|L|+|R|) ──┐                  │
                               │                          ├─ AutoMakeup       │
                               └─ curveDrive → curve ────┴─→ dOut[b]         │
                                        │                     (1/base sample)  │
                                        │                          │          │
                                        └─ wet · makeup[b] · vol · pan · solo ─┤
                                                     ↑                          │
                                       auto ? gainS[b] : MAKEUP knob           │
                                                                                │
                              Σ bandas → DC(15 Hz) → ·mix ─────────────────────┤
                                                                                │
                                             out = (dryTerm + wetTerm) · outVol ┘
```

Invariantes del diagrama:

1. `dIn` **no** ve `drive` ni la curva (§0/E3).
2. `dOut` **no** ve `vol`, `pan` ni `solo`: hacer solo una banda no cambia la calibración (§7/R7).
3. `dOut` **no** ve el makeup: la realimentación no puede auto-excitarse.
4. El detector se actualiza una vez por muestra base, después de aplicar el `mk[]` de esa muestra (retardo de 1
   muestra base).

### 4.5 Enmienda de coordenadas (`y = 155.0`, no `147.4`) y tabla de ocupación

/** AC4 sobre 9 curvas x n = 1/4 (18 medidas de 2 s). Sin allocation en el

AutoGainResult measureAutoGain(void) {
  AutoGainResult r = {0.0, 0.0};
  for (int c = 0; c < coaldynamics::CURVE_COUNT; ++c) {
    for (int k = 0; k < 2; ++k) {
      const int n = (k == 0) ? 1 : 4;
      cdt::OfflineChain ch;
      ch.p.lr4 = 1;                 // obligatorio (5.3)

      ch.configure(FS, n);
      configureCurves(ch, c, 11.f); // drive 1.0 -> 1 + 10*1
      ch.p.volLow = ch.p.volMid = ch.p.volHigh = 1.f;
      ch.p.mix = 1.f;
      ch.p.outVol = 1.f;

      std::vector<float> in, out;
      runSineAmp(ch, 1000.0, 2 * static_cast<int>(FS), 0.1, in, out);

      const std::size_t from = static_cast<std::size_t>(0.2 * FS);  // 200 ms
      const double dev = cdt::db20(cdt::rms(tailFrom(out, from)) /
                                   cdt::rms(tailFrom(in, from)));
      if (std::fabs(dev) > r.worstDev)
        r.worstDev = std::fabs(dev);

      // p-p: RMS por ventanas de 10 ms (480 muestras = 10 periodos de 1 kHz).
      double lo = 1e9;
      double hi = -1e9;
      for (std::size_t i = from; i + 480 <= out.size(); i += 480) {
        double acc = 0.0;
        for (std::size_t j = 0; j < 480; ++j) {
          const double v = static_cast<double>(out[i + j]);
          acc += v * v;
        }
        const double d = cdt::db20(std::sqrt(acc / 480.0));
        if (d < lo) lo = d;
        if (d > hi) hi = d;
      }
      if (hi - lo > r.worstPp)
        r.worstPp = hi - lo;
    }
  }
  return r;
}
```

### 7.2 Invariantes verificables

1. `autoMakeup = 0` ⇒ la salida es **bit-idéntica** a v2.6.0 (los 13 casos existentes lo verifican; `mk = 1.0f`).
2. `autoMakeup` se lee **una** vez por muestra base (`relaxed`); jamás por submuestra ni por banda dentro del bucle.
3. `AutoMakeup::update()` se llama **una** vez por muestra base, en la última submuestra, con los tres detectores a
   la vez.
4. Cero allocation, cero I/O, cero `std::` y cero símbolos de Rack en `src/AutoMakeup.hpp`.
5. `NUM_PARAMS == 20`, ids 0–19 sin cambios, `*_MAKEUP` = 20/21/22.
6. `applyOversampling()`/`applyCrossover()`/`applyAdaa()` **no** resetean `autoMakeupDsp`.
7. El JSON escribe `"autoMakeup"` siempre y lo lee sólo con `json_is_true`; ausente ⇒ Off.
