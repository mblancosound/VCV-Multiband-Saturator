## 0. Resumen ejecutivo (short summary para el orquestador)

Dos features **opt-in** que cierran las dos deudas DSP de calidad dejadas abiertas en specs anteriores
(`specs/curves_spec.md` §10, `specs/oversampling_spec.md` §6) y detectadas en la auditoría (`C7`):

1. **F1 — Crossover Linkwitz-Riley 4º orden** (`"crossover": "legacy" | "lr4"`, **default `"legacy"`**):
   LP y HP 4º orden complementarios + banda Mid derivada como `x − low − high` → **reconstrucción perfecta**

   §4.1; `TUBE`/`DIODE` fuera de alcance).

Alcance estricto de esta spec: **dos features opt-in y nada más**. Cero params/inputs/lights nuevos. Claves
JSON nuevas: `"crossover"` y `"adaa"`.

Contrato de IDs: **CERO** params nuevos (0..16 intactos, `NUM_PARAMS = 17`), **CERO** inputs (0..7), **CERO** lights
(6). Reservados para otra spec (no tocar aquí): params 17-19 LOW/MID/HIGH_DRIVE_CV, inputs 8-10 LOW/MID/HIGH_DRIVE_INPUT,
params 20-22 LOW/MID/HIGH_MAKEUP, claves `"autoMakeup"`, `"bypass"`.

Decisiones de contrato: ambos modes/flags son **aditivos con default = comportamiento v2.5.0** (patch v2.5.0
bit-idéntico); ambos son **undoables desde el menú contextual** con Rack history (patrón `pushXxxHistory`).

Versión objetivo del plugin: **2.6.0** (minor, por el criterio del repo: feature user-facing → minor).

## 1. Objetivo y no-objetivos

### 1.1 Objetivo

- **F1**: con `"crossover": "lr4"`, el módulo procesa LP4 y HP4 (4º orden Butterworth, cascada de dos BQ de
  2º orden con Q = 0,707, normalizados como complementarios) y calcula la banda Mid como `x − low − high`, de modo
  que la suma `low + mid + high` reconstruye la entrada **por construcción** (sum = low + (x − low − high) + high = x).
- **F2**: con `"adaa": true`, las curvas seleccionadas se evalúan con ADAA1 (`y = (F(u) − F(u_prev)) / (u − u_prev)`,
  fallback a la curva directa si `|u − u_prev| < ε`). `CLEAN` es la excepción explícita: al ser lineal no genera alias
  y se evalúa siempre de forma directa (§4.1, §4.4).

### 1.2 No-objetivos (explícitos)

- **No** se toca el orden de las curvas (`CurveId`, `applyCurve(u, curve)`, `TRIM[]`, `curveDrive()`).
- **No** se tocan los IDs (params/inputs/outputs/lights) ni el número de params.
- **No** se cambia el sonido por defecto: con defaults (`"crossover": "legacy"`, `"adaa": false`) el módulo debe
  sonar **bit-idéntico** a v2.5.0.
- **No** se implementa bypass, gains automáticos (`"autoMakeup"`), makeup params, ni panel/SVG nuevo (fuera de alcance).
- **No** se reordena ni se renombran claves JSON existentes (`"oversampling"`, `"curves"`, `"solo"`, `"linkCurves"`).
- **No** se añaden params, inputs, outputs, lights ni controles de panel nuevos en esta iteración.

## 3. F1 — Crossover Linkwitz-Riley 4º orden con reconstrucción perfecta (opt-in)

### 3.1 Matemática del LR4

- **Legacy**: LP 250 / BP 1000 / HP 4000 (BQ por rama, Q = 0,707 / 1,0 / 0,707) → solapes → ripple de la suma
  (`+1,00 dB @1 kHz`, `−2,06 dB @2,5 kHz`).
- **LR4**: LP4 = cascada de **dos BQ de 2º orden Butterworth (Q = 0,707)**:
  - BQ-1: lowpass, `f0 = 250 / fsN` (fsN = sampleRate × oversampling);
  - BQ-2: lowpass, `f0 = (250 × √2) / fsN`.
  - HP4 = cascada análoga: highpass, `f0 = 4000 / fsN` y `f0 = (4000 × √2) / fsN` (Q = 0,707), o HP4 como
    complementario de LP4 (`|HP4|² = 1 − |LP4|²`).
- **Mid**: `mid = x − low − high` → `low + mid + high = low + (x − low − high) + high = x` (suma exacta en
  aritmética real). Con drive = 0 y curva `CLEAN` (ruta lineal), la salida wet = la entrada ideal (× `TRIM[CLEAN]`)
  → reconstrucción plana por construcción.

**Recalculación y Regla 3**: los coeficientes se recalculan en `updateFilterFrequencies()` (rama `legacy` /
  `lr4`) **y** en `onSampleRateChange()` (que ya delega en `updateFilterFrequencies()`), siempre con
  `fsN = sampleRate × oversampling`. El modo no se hardcodea en el DSP: se lee del estado aplicado y se usa para
  elegir topología. Nada de allocs en `process()`.

### 3.3 Estados nuevos

### 3.4 Decisión de reset y click

- Al cambiar de modo se **resetean los estados de filtro y se recalculan coeficientes** (`reset` + `updateFilterFrequencies()`).
- **Decisión (2026-10-28)**: adoptar **reset + recálculo + click documentado como aceptado** (mismo criterio que el
  click del cambio de oversampling, `specs/oversampling_spec.md` §6); la alternativa de **crossfade/rampa de
  coeficientes se descarta** para esta iteración porque las topologías no son anidadas (cascada LP4/HP4 vs LP/BP/HP).

### 3.5 Coste CPU (declarado)

- Legacy (1x): 6 BQ por bloque estéreo (LP/BP/HP × L/R).
- LR4 (1x): 8 BQ por bloque estéreo (LP4 = 2 stages + HP4 = 2 stages × L/R) → **delta +33 %** en el bloque de filtros.
- Por submuestra (a fsN): legacy 3 BQ por canal/muestra; LR4 4 BQ por canal/muestra (2 para LP4 + 2 para HP4).
- Sin cambio de latencia (dry delay OS_LATENCY = 15 intacto; la resta Mid no añade latencia al sum).

## 4. F2 — ADAA de primer orden en las curvas suaves (opt-in)

### 4.1 Tabla curva → antiderivada → coste → ¿incluida?

ADAA1: `y = (F(u) − F(u_prev)) / (u − u_prev)`; si `|u − u_prev| < ε` → fallback a la curva directa `f(u)`.

| Curva | `F(u) = ∫f(u)du` (cerrada) | Coste de `F` | ADAA en v2.6.0 |
|---|---|---|---|
| `CLEAN` | `u²/2` (lineal) | trivial | **NO** (lineal ⇒ no genera alias; el ADAA degeneraría en el filtro `(u+u_prev)/2`) |
| `TANH` | `u·tanh(u) − ln(cosh u)` (con `ln cosh` estable) | baja (log/cosh) | **SÍ** |
| `CUBIC` | polinómica (con tramos) | trivial | **SÍ** |
| `ARCTAN` | polinómica + atan | baja | **SÍ** |
| `HARD` | `0.5·u²` por tramos (clamp ±1) | trivial | **SÍ** |
| `FOLDBACK` | piecewise cuadrática (ola triangular plegada) | baja | **SÍ** |
| `SINEFOLD` | `−cos(u)` | trivial | **SÍ** |
| `TUBE` | vía `ln cosh` (razón de tanh) | media | **NO** (fuera de alcance v2.6.0) |
| `DIODE` | vía exponencial | baja | **NO** (fuera de alcance v2.6.0) |

**Decisión (2026-10-28)**: ADAA se incluye para `TANH, CUBIC, ARCTAN, HARD, FOLDBACK, SINEFOLD`
(`F` cerrada y de baja coste). **FUERA DE ALCANCE**: `TUBE` y `DIODE` quedan con evaluación directa (sin ADAA) en
esta iteración; se declara explícitamente y queda abierta su inclusión a una iteración futura. `CLEAN` queda
excluida por diseño (lineal, sin alias que corregir) y con `"adaa": true` se evalúa de forma directa, bit-idéntica
al modo sin ADAA.

> **Corrección (2026-10-30)**: en la revisión de 2026-10-28 `CLEAN` figuraba como curva con ADAA. Era un error: `f(u) = u`
> es lineal, no genera armónicos y por tanto no puede aliarse; su antiderivada `F(u) = u²/2` hace que el paso ADAA
> devuelva `(u + u_prev)/2`, un promedio de dos muestras con `|H(ω)| = cos(ω/2)` (−3,9 dB @ 20 kHz y cero en Nyquist a
> 48 kHz). Es decir, un filtro de agudos no anunciado sobre la curva que existe precisamente para pasar la banda limpia
> y level-matched. Se corrige aquí, en §4.2, §4.3, §5, §7, §8 y apéndices C/B.

### 4.2 Tabla de alias esperado por curva y factor

Baseline (arnés, 4x, 5 kHz, 5 V, drive 11, peor alias in-band no armónico <20 kHz relativo al fundamental):

| Curva | Baseline 4x | Objetivo con ADAA 4x (≤ baseline − 6 dB) | ¿Cumple ≥6 dB? |
|---|---:|---:|---|
| `TANH` | −25,9 dB | ≤ −31,9 dB | SÍ (medido como mejora declarada) |
| `FOLDBACK` | −8,2 dB | ≤ −14,2 dB | **SÍ (criterio obligatorio)** |
| `SINEFOLD` | −6,4 dB | ≤ −12,4 dB | **SÍ (criterio obligatorio)** |
| `CUBIC` | −22,8 dB | ≤ −28,8 dB | previsto |
| `HARD` | −24,2 dB | ≤ −30,2 dB | previsto |
| `TUBE` | −23,5 dB | — (sin ADAA) | NO (fuera de alcance) |
| `DIODE` | −26,9 dB | — (sin ADAA) | NO (fuera de alcance) |

`CLEAN` no tiene fila de alias porque es lineal (no genera componentes fuera de banda); se cubre con el caso
T-ADAA-CLEAN de §7.

### 4.3 Nivel / TRIM

ADAA1 con `F` cerrada no debe introducir cambio de ganancia intrínseco en `TANH`/`SINEFOLD` (el paso `Δ = u − u_prev`
es la variable de la integral). **Decisión (2026-10-28)**: en v2.6.0 **no se compensa con `TRIM`** (fuera de alcance;
`TRIM` sigue siendo calibración de la curva directa); cualquier desviación se mide con el arnés.

`CLEAN` queda excluida del ADAA (§4.1), por lo que la media `(u+u_prev)/2` no se aplica en ninguna ruta y no hay
filtro de agudos oculto. Con `"adaa": true` y curva `CLEAN` la salida es **bit-idéntica** a `"adaa": false`
(caso T-ADAA-CLEAN, §7).

### 4.4 Nota de implementación (2026-10-30): historial, `CLEAN` y cambio de curva

- En `processBands()` el `switch` de ADAA debe **saltar el bloque de historial para `CLEAN`**: se evalúa `y = f(u)`
  directamente y **no se actualizan** `u_prevLow*`, `u_prevMid*`, `u_prevHigh*` de esa banda (ni se leen). La ruta
  es entonces la misma instrucción que con `"adaa": false` → salida bit-idéntica, sin media de dos muestras.
- Al cambiar de curva con ADAA activo, **sincronizar `u_prev = u` en el primer bloque** tras aplicar el cambio, para
  evitar el transitorio de `(F(u) − F(u_prev))` calculado con historia de otra curva. El sincronismo se hace **por
  banda (low / mid / high) y por canal (L / R)**: 6 sincronizaciones independientes, y solo en el bloque en que se
  detecta el cambio de curva aplicado (coste cero en régimen permanente).
- `u_prev*` se resetean además en `applyOversampling()`, `applyCrossover()` y `onReset()` (misma ruta de reset, §3.3).

## 6. Compatibilidad de patches

- Claves nuevas: `"crossover"` (string: `"legacy" | "lr4"`) y `"adaa"` (boolean: `false | true`).
- Defaults: `"crossover": "legacy"`, `"adaa": false`. Valores ausentes o inválidos → defaults.
- Patch **v2.5.0** (sin claves): carga con legacy + ADAA off → **bit-idéntico** a v2.5.0.
- Guardado (`dataToJson`): se escriben ambas claves siempre (mismo patrón que `"oversampling"` / `"solo"` / `"linkCurves"`).
- Lectura (`dataFromJson`): estricta; `"crossover": "lr4"` activa LR4; cualquier otro valor → legacy;
  `"adaa": true` activa ADAA; cualquier otro valor → off.
- Undo/cambio desde menú no registra historial al cargar patch (regla v2.4.0).

## 8. Riesgos y mitigaciones

| ID | Riesgo | Mitigación |
|---|---|---|
| R1 | ADAA con `|u − u_prev| < ε` → división por cero | ε fijo (p. ej. 1e-4); fallback a curva directa |
| R2 | Historial ADAA stale al cambiar oversampling/reset | Reset en `applyOversampling()` y `onReset()` |
| R3 | Click al cambiar modo crossover | Decisión: reset + recompute + click aceptado (crossfade descartado) |
| R4 | CPU: LR4 (+33 % BQ) + ADAA (F en curvas) | Presupuesto declarado; verificar con arnés/timing |
| R5 | THD+N TANH con ADAA podría degradar > 0,5 dB | Criterio 5 lo impone; ajustar ε/F si falla |
| R6 | Nivel ADAA en curvas no lineales | Decisión: no compensar con `TRIM` en v2.6.0; `CLEAN` excluida del ADAA (§4.1) para no introducir filtro de agudos |

## Apéndices del arquitecto (entregables)

### A. Diagrama DSP (ASCII)

```
 IN_L/R
   │
   ├─ dry ────────────────► delay OS_LATENCY (15) ──┐
   │                                             │
   │  up ×N (Q=16, cutoff 0.95)                  │
   │     │                                    │
   │     ├─ LP4 ──► low  ──► curve(low)  ──┐   │
   │     ├─ HP4 ──► high ──► curve(high) ─┼──►► wet sum ─► DC-blocker ─► MIX ─► OUT
   │     └─ Mid = x − low − high ─► curve(mid) ─┘
   │                                             │
   └─────────────────────────────────────────────┘  (down ×N)
```

### B. Pseudocódigo de las ecuaciones clave

```
ADAA1:
  u    = curveDrive(banda, drive, curve)     // CLEAN: u = banda ; resto: banda*drive
  if (!adaa || curve == CLEAN) {
    y = curveDirect(u, curve)                // ruta directa: sin historial, sin media (u+u_prev)/2
    // NO se toca u_prev de esta banda  -> con CLEAN, bit-idéntico a "adaa": false
  } else {
    y = curveDirect(u, curve)                // fallback
    if (|u - u_prev| >= ADAA_EPS) {
      y = (curveF(curve, u) - curveF(curve, u_prev)) / (u - u_prev)   // ADAA1
    }
    u_prev = u
    // cambio de curva con ADAA activo: u_prev = u en el primer bloque (por banda y por canal)
  }
  out = y * TRIM[curve]

LR4:
  fsN = sampleRate * oversampling
  if (crossover == LR4) {
    low  = LP4(x, fsN)    // BQ2 @ 250/fsN + BQ2 @ 250*sqrt(2)/fsN
    high = HP4(x, fsN)    // BQ2 @ 4000/fsN + BQ2 @ 4000*sqrt(2)/fsN
    mid  = x - low - high
  } else {
    low  = LP(x, 250/fsN, Q=0.707)
    mid  = BP(x, 1000/fsN, Q=1.0)
    high = HP(x, 4000/fsN, Q=0.707)
  }
  wet = curve(low) + curve(mid) + curve(high)
```

### C. Presupuesto de CPU y latencia

- Latencia: sin cambios. OS_LATENCY = 15 base muestras (2x/4x/8x), 0 en 1x; ADAA añade 1 muestra de historia (misma
  ventana); LR4 no añade latencia al sum. Dry delay intacto.
- CPU: LR4 delta +33 % en BQ (6 → 8 por bloque estéreo, 1x); ADAA sobre curvas con F (TANH/CUBIC/ARCTAN/HARD/
  FOLDBACK/SINEFOLD; `CLEAN` excluida, §4.1). Declarado estimado; **verificar** con arnés/timing y CPU meter del host.

### D. Contrato para el implementador (recap)

- Regla de oro RT: prohibido en `process()` (y en todo callback de audio): `new` / `delete` / `malloc` / `free` /
  `std::make_unique` / `std::make_shared`, `vector::push_back` / `resize`, `std::string` que aloque, y cualquier I/O
  (ficheros, red, logs, `printf`, `std::cout`). Todo el estado nuevo es de tamaño fijo en la clase (p. ej. el
  historial ADAA: 6 floats); buffers preasignados en `onAdd` / constructor / `onSampleRateChange`; buffers de
  tamaño fijo en `processBands` (`float highL[N]` …). Sin allocs dinámicos ni I/O en el hilo de audio.
- Regla de oro RT: todo coeficiente (crossovers, envolventes, LFOs, delays, oversamplers) se recalcula desde
  `args.sampleRate` en `onSampleRateChange()` / `applyOversampling()`; nada de constantes calculadas para 44,1 kHz.
