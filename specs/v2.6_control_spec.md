## 4. G1 — CV de Drive por banda

### 4.1 Ley exacta (decisión cerrada: opción (a), lineal en unidades de knob)

```
knobEff_b = clamp( knob_b + (V_b / 10) * att_b , 0 , 1 )
drive_b  = 1 + 10 * knobEff_b          // drive ∈ [1, 11]
```

donde:
- `knob_b = params[LOW_DRIVE|MID_DRIVE|HIGH_DRIVE].getValue() ∈ [0,1]`
- `V_b = inputs[LOW_DRIVE_INPUT|MID_DRIVE_INPUT|HIGH_DRIVE_INPUT].getVoltage() ∈ [-10,10] V`
- `att_b = params[LOW_DRIVE_CV|MID_DRIVE_CV|HIGH_DRIVE_CV].getValue() ∈ [-1,1]`

**Justificación de la opción (a):** el drive vive en `1..11` (= `1 + 10*knob`), de modo que "unidad de knob" = 10 unidades de drive. Modular linealmente en unidades de knob (`knob + (V/10)*att`, clamp a `[0,1]`) es **inversible con el knob**, es coherente con el patrón pan/vol (`clamp(P + (V/10)*A, min, max)`) y con el divisor unificado `/10` de `specs/cv_scaling_fix_spec.md`. Es la opción (a) recomendada del brief y se adopta.

**Rango de modulación:** con `att = +1` y `V = +10` → `knobEff = 1` → `drive = 11` (saturación máxima); con `V = −10` → `knobEff = −1` → `drive = 1` (sin saturación). El clamp a `[0,1]` del valor efectivo impide fuera de rango. Equivalencia literal con la opción (a) del brief: `drive = clamp(1 + knob*10 + (V/10)*att*10, 1, 11)`.

### 4.2 Algoritmo y resolución

- En `process()`, junto a la resolución de pan/vol: `p.driveLow = 1 + 10*clamp(knobLow + (V_Low/10)*attLow, 0, 1)`, idem Mid/High.
- **Estado nuevo:** ninguno. Se **reutilizan** los campos `float driveLow, driveMid, driveHigh;` de `OSParams` (`Saturator.hpp:73-74`), que pasan a incorporar el término CV. Sin buffers, sin allocs, sin estructuras nuevas.
- **Cadena:** dentro de `processBands<Stage>` vía `applyCurve(curveDrive(banda, p.driveX, p.curveX), p.curveX)` — para `CLEAN` el drive no aplica (patrón `curveDrive`).

### 4.3 JSON

- **Sin clave JSON nueva**: los atenuadores `*_DRIVE_CV` son params nativos (persistidos por Rack). Claves reservadas (`"crossover"`, `"adaa"`) no se usan.

### 4.4 Coste CPU

- Por muestra base: 3 lecturas param + 3 lecturas input + 2 clamps/add + mult. **Despreciable**; sin allocations.

## 5. G2 — Makeup por banda + Auto-gain

### 5.1 Makeup (params nuevos 20–22)

| Param | Id | Rango | Default | Unidad |
|---|---|---|---|---|
| `LOW_MAKEUP` | 20 | `[0, 4]` | **1.0** | lineal (`×g`; 1.0 = 0 dB = 100 %; 4.0 = +12.04 dB ≈ 400 %) |
| `MID_MAKEUP` | 21 | `[0, 4]` | **1.0** | idem |
| `HIGH_MAKEUP` | 22 | `[0, 4]` | **1.0** | idem |

- **Decisión:** rango `[0, 4]`, default `1.0`. Justificación: el drive comprime (out ≤ in) ⇒ makeup correctivo ≥ 0 dB; límite inferior "sin makeup" (`0`) y superior +12 dB (`4`). Se rechaza el bipolar `[-1, 1]` (el punto 0 dB no es simétrico para una ganancia correctiva post-compressión).

### 5.2 Auto-gain (clave JSON `"autoMakeup"`, default `false`)

- Estado: `std::atomic<int> autoMakeup{0};` (0 = Off, 1 = On; escrito UI/JSON, leído audio con `memory_order_relaxed` — patrón `curves`/`solo`).
- Algoritmo (RT-safe, sin allocations, sin look-ahead):
  - **Tiempo de asentamiento:** el gain auto-calibrado (`gainS`) parte de `1.0` y se suaviza con one-pole (`coefSmooth = exp(-1/(fs*0.010))`, 10 ms) hasta converger; el envelope converge con attack/release (10 ms / 100 ms).
  - Coeficientes one-pole recalculados en `onSampleRateChange()` (y en ctor): `coefAttack = exp(-1/(fs*0.010))` (10 ms), `coefRelease = exp(-1/(fs*0.100))` (100 ms), `coefSmooth = exp(-1/(fs*0.010))`.
  - Envolvente: `envIn[b] += coefAttack*(fabs(x_b) - envIn[b])` (entrada de banda, post-crossover, pre-curva); `envOut[b] += coefRelease*(fabs(y_b) - envOut[b])` (salida de curva, post-TRIM).
  - Ganancia: `gain[b] = clamp(envIn[b] / (envOut[b] + 1e-6), 0, 4)`; suavizado: `gainS[b] += coefSmooth*(gain[b] - gainS[b])`.
  - Ganancia efectiva: `effMakeup[b] = autoMakeup ? gainS[b] : params[MAKEUP_b].getValue()`.
- **Estado nuevo** (tamaño fijo, inicializado en ctor / recalculado en SR change): `float envIn[3], envOut[3], gain[3], gainS[3]; float coefAttack, coefRelease, coefSmooth;`
- **Posición en cadena:** tras la curva (y su TRIM), antes de `* vol * pan * solo`:
  `y_out = applyCurve(...) * effMakeup_b * vol_b * pan_b * soloGain_b`.
- **Interacción:** **Auto-gain ON ignora el makeup manual** (auto manda). Auto-gain OFF usa el makeup manual (default `1.0` = 0 dB).
- **Coste CPU:** ~3 × (1 env + 1 división + 1 smooth) por sub-muestra/banda; despreciable frente a `tanh`/biquads.

### 5.3 Criterio medible (G2)

- Seno **1 kHz a −20 dBFS**, **drive 100 %**, **Tanh**, **Auto-gain ON** → el nivel de salida queda dentro de **±1 dB** del nivel de entrada; en las **9 curvas** y en **1x/4x**; sin oscilación audible; desviación pico-a-pico del nivel tras **200 ms** ≤ **0.5 dB**.

## 6. G3 — Bypass + `onReset()`

### 6.1 Bypass

- Clave JSON: `"bypass": false` (default Off). Accesible **sólo** por menú contextual (no param, no panel, no widget dedicado).
- Estado: `std::atomic<int> bypass{0};` (0 = Off, 1 = On; escrito por UI/JSON, leído por audio) + `float bypassGain = 1.f;` (rampa; tipo `float`, tamaño fijo, inicializado en ctor).
- **Conmutador:** rampa lineal con `step = args.sampleTime * 200.f` (≈5 ms), mismo patrón que `soloGain`; target = `bypass ? 0 : 1`. **Decisión:** se usa ramparse (~5 ms, patrón `soloGain`) para no hacer click. Se actualiza una vez por muestra base en `process()`.
- **Salida (sustitución del punto de mix/dry):**
  ```
  outL = ( dryL*(1−mix)*dryGain + wetL*mix ) * outVol * bypassGain
       + inL * outVol * (1 − bypassGain);
  outR = ( dryR*(1−mix)*dryGain + wetR*mix ) * outVol * bypassGain
       + inR * outVol * (1 − bypassGain );
  ```
- Casos:
  - `bypassGain = 1`: ruta idéntica a v2.5.0 (bit-exacta: `x*1 + y*0 = x`).
  - `bypassGain = 0`: `out = in * outVol` (sin crossover, sin curva, sin DC-blocker, sin retardo de dry, sin wet).

### 6.2 `onReset()` — estado a resetear

- **Propiedad:** `onReset()` es propiedad de la **spec de control** (`specs/v2.6_control_spec.md`, G3/bypass); la `specs/v2.6_quality_spec.md` remite el reset del historial ADAA a este punto y no declara por sí misma el override del módulo.

- **Reset del historial ADAA:** el reset de los 6 floats de historial (`u_prevLowL/R`, `u_prevMidL/R`, `u_prevHighL/R`) se hará **llamando a `resetAdaaHistory()`** desde el `onReset()` — método que implementará la spec de calidad (F2/ADAA) — poniendo esos valores a su estado inicial.

- **Lista exhaustiva de estado a resetear en `onReset()`:** biquads (L/R × low/mid/high), stages de oversampling, `dryBufferL/R`, `dryIndex`, `dryDelay` (→ derivado), `dcR` + `dcX1L/R`, `dcY1L/R`, `soloGain[3]`, `dryGain`, `satMeters`, `bypassGain` (→ 1), `bypass` (→ Off), envelopes auto-gain (`envIn`, `envOut`, `gainS` → iniciales) **y** `resetAdaaHistory()` (reset del historial ADAA: `u_prevLowL/R`, `u_prevMidL/R`, `u_prevHighL/R` → iniciales). **No** toca params ni claves JSON.

### 6.3 Interacción con oversampling / dry

- Bypass correcto a 1x/2x/4x/8x: con `bypassGain=0` la salida usa `in` directo (sin retardo de 15 samples); con `bypassGain=1` la ruta vieja (dry con retardo, wet oversampling) se conserva.
- `applyOversampling()` **no** resetea `bypassGain` (es ganancia en rampa, no estado crítico).

## 7. Diagrama DSP (texto) y pseudocódigo de las ecuaciones clave

```
 IN_L ──┬─────────────────────────────────────────────────────────────┬───────────────────────────► OUT
        │                                                             │
        │  DRY: in → delay (OS_LATENCY) → (1−mix)*dryGain              │
        │  WET: in → up×N → LP/BP/HP → curve → makeup/auto → vol*pan*solo → Σ → DC(15 Hz) → mix → *outVol
        │                                                             │
        └─────────────────────────────────────────────────────────────┘
         bypass:  out = wetTerm*bypassGain + in*outVol*(1−bypassGain)
         bypassGain=1 → ruta v2.5.0 (bit-exacta). bypassGain=0 → out = in*outVol.
```

Pseudocódigo G1 (drive CV):
```
drive_b = 1 + 10 * clamp( knob_b + (V_b / 10) * att_b , 0 , 1 );   // ∈ [1, 11]
```

Pseudocódigo G2 (auto-gain):
```
coefAttack  = exp(-1 / (fs * 0.010));
coefRelease = exp(-1 / (fs * 0.100));
coefSmooth  = exp(-1 / (fs * 0.010));
envIn[b]  += coefAttack  * (fabs(x_b)  - envIn[b]);
envOut[b] += coefRelease * (fabs(y_b) - envOut[b]);
gain[b]   = clamp(envIn[b] / (envOut[b] + 1e-6), 0, 4);
gainS[b]  += coefSmooth * (gain[b] - gainS[b]);
effMakeup[b] = autoMakeup ? gainS[b] : params[MAKEUP_b].getValue();
```

Pseudocódigo G3 (bypass):
```
out = ( dryTerm * outVol + wetTerm * outVol ) * bypassGain
    + in * outVol * (1 - bypassGain);
// bypassGain=1 → out = (dryTerm + wetTerm) * outVol   [ruta v2.5.0]
// bypassGain=0 → out = in * outVol                     [bypass]
```

## 9. Interacciones

| Interacción | Comportamiento |
|---|---|
| Solo | En bypass ON, el solo queda subordinado (out bypassed = `in*outVol`); con bypass OFF, solo opera como antes. |
| Mix | En bypass ON, mix se ignora; con bypass OFF, mix opera como antes. |
| Dry delay | En bypass (`bypassGain=0`) se usa la entrada directa: **sin retardo** de 15 samples. |
| Metering | Los stages siguen corriendo en bypass; los `satMeters` se actualizan como de costumbre (no se resetean). |
| Undo / Redo | Acción nueva `BypassAction` (name `"toggle bypass"`) + helper `pushBypassHistory` (patrón `SoloAction`). |
| Copy curve | No cambia; en bypass la curva no se aplica. |
| Link curves | No cambia. |
| Oversampling | No cambia; bypass correcto a 1x/2x/4x/8x. |
| Auto-gain ↔ Makeup | Auto-gain ON **ignora** makeup manual (auto manda). |

## 13. Riesgos, mitigaciones, presupuesto, verificación manual

### 13.1 Riesgos y mitigaciones

| ID | Riesgo | Prob. | Impacto | Mitigación |
|---|---|---|---|---|
| R1 | **Pumping / oscilación** en auto-gain con seno estacionario | MEDIA | audible | Attack/release/smooth one-pole; medir p-p tras 200 ms (AC4). |
| R2 | **Click** al conmutar bypass | BAJA | audible | Rampas con `step = args.sampleTime*200` (patrón solo); verificar rampa (AC5). |
| R3 | **Fuera de rango** drive (clamp) | BAJA | bajo | Clamp a `[0,1]` de knob-eff; drive ∈ [1,11]. |
| R4 | **Incompatibilidad de patch** | BAJA | alto | Defaults neutros (att=0, makeup=1.0); JSON ausente → off/defecto. |
| R5 | **Coste CPU** de envolventes | BAJA | bajo | Despreciable (< ~1 % del camino); sin allocs. |

### 13.2 Presupuesto CPU / latencia / memoria

- **CPU:** G1 ≈ 0 adicional; G2 ≈ 3×(env + div + smooth)/sub-muestra/banda (despreciable); G3 ≈ 2 mults. Estimación conservadora, **sin medición propia** (verificación con el arnés / medición en Rack).
- **Latencia:** declarada sin cambio (0 / 15 samples en 1x/2x/4x/8x); bypass añade retardo 0 (usa `in` directo). Rampa 5 ms no añade latencia de bloque.
- **Memoria:** nuevo estado fijo (< ~200 B): `bypassGain` (4 B), `bypass` atómico menor, `envIn/envOut/gain/gainS` (12 × 4 B) + coefs. Todo preasignado en ctor / `onSampleRateChange`.

### 13.3 Verificación manual en Rack

1. Bypass: menú contextual → activar/desactivar; comprobar out = `in*outVol` y ausencia de retardo con oversampling 4x; Ctrl+Z / Ctrl+Shift+Z.
2. CV drive: +10 V / −10 V con atenuadores (Low/Mid/High) → drive 11 / drive 1; con atenuador 0 → sin CV.
3. Makeup: knobs 0..4; auto-gain ON/OFF.
4. `onReset()`.

## 14. Resumen corto para el orquestador

1. **G1:** drive CV lineal en unidades de knob: `drive = 1 + 10*clamp(knob + (V/10)*att, 0, 1)`.
2. **G2:** makeup `[0,4]`, default 1.0 (0 dB); auto-gain `"autoMakeup"` (attack 10 ms / release 100 ms / smooth 10 ms, clamp [0,4], eps 1e-6); auto manda.
3. **G3:** bypass `"bypass"` (menú + undo), rampa 5 ms, out = `in*outVol` en bypass, stages siguen.
4. IDs nuevos 17–22 params, 8–10 inputs; `NUM_*` → 23/11; nunca reindexar. Claves reservadas no usadas.
5. Gate: build limpio + AC1..AC6.
