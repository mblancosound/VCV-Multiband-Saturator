## 3. Contrato resultante (post-2.8.2)

| Param | IDs | Min | Max | Default | Display dB | Dominio DSP |
|---|---|---|---|---|---|---|
| `*_MAKEUP` (Low/Mid/High) | 20/21/22 | **1.0** | **3.9810717** | **1.0** | **0.00 .. +12.00** | **boost-only (×g, g ∈ [1.0, 3.9810717])** |

- Rango lineal resultante: `1.0 .. 3.9810717` == `10^(12/20)` == `0 .. +12.00 dB` (medido con `20*log10`).
- Default `1.0` -> display `0.00 dB` (extremo inferior) = identidad = punto de arranque boost-only.
- El knob solo puede boostear: no puede atenuar (< 1.0 = < 0 dB). Con `*_VOL` (0..1 = 0..100 %) el dominio de makeup (>= 1.0) y el de volumen (<= 1.0) quedan disjuntos: el makeup solo boostea y el volumen solo atenua. Es la justificacion funcional del cambio solicitado.

## 6. Riesgos

| # | Riesgo | Impacto | Mitigacion |
|---|---|---|---|
| R1 | Remapeo de patches v2.8.1 al nuevo rango | medio | VCV guarda el valor normalizado por indice; al cambiar min/max los patches antiguos se reasignan al nuevo rango (un makeup antiguo por debajo de 0 dB pasa a >= 0 dB). Efecto esperado del cambio de rango pedido; no se corrompen los patches. |
| R2 | Display `+12.00` vs `+12.04` | bajo | Max nuevo = 10^(12/20) = 3.9810717 -> `20*log10(3.9810717) = +12.00` exacto; antes `4.0` -> `+12.04`. Display nuevo correcto y sin drift. |
| R3 | `-inf` inalcanzable | bajo | Con min `1.0` (> 1e-6) la guarda `v <= 1e-6f` del override de display ya no se dispara; se mantiene como defensa (minimo cambio). |
| R4 | Auto-makeup | bajo | `AutoMakeup` mantiene el clamp interno de ganancia (`min(g, 4.f)`, `src/AutoMakeup.hpp:61`) e ignora el knob manual cuando auto esta ON. Fuera de alcance: no se toca; el dominio interno auto queda en 4x (+12.04 dB) mientras el manual pasa a +12.00 dB. |
